# AEO — Answer Engine Optimization

How this site makes sure ChatGPT, Claude, Perplexity, Copilot, Gemini/AI
Overviews and search crawlers can find, read, trust and cite every page.
Companion to `docs/SEO.md` (classic SEO) — this file covers the AI side.

## 1. Crawler access (`public/robots.txt`)

No engine may index what it cannot fetch, so every major AI/LLM crawler is
explicitly allowed (not just `User-agent: *`):

| Engine family | User-agents allowed |
|---|---|
| OpenAI (ChatGPT + Search) | `GPTBot`, `OAI-SearchBot`, `ChatGPT-User` |
| Anthropic (Claude) | `ClaudeBot`, `Claude-Web`, `Claude-SearchBot`, `anthropic-ai` |
| Perplexity | `PerplexityBot`, `Perplexity-User` |
| Google AI Overviews/Gemini | `Google-Extended`, `GoogleOther` (+ standard Googlebot via `*`) |
| Apple Intelligence | `Applebot`, `Applebot-Extended` |
| Copilot/Bing | `Bingbot` |
| Others | `DuckAssistBot`, `Amazonbot`, `meta-externalagent`, `FacebookBot`, `Bytespider`, `cohere-ai`, `MistralAI-User`, `YouBot`, `AI2Bot`, `Timpibot`, `CCBot` |

Only the noindex utility pages (`404`, `access-denied`, `maintenance`) and
template partials are disallowed, to keep crawl budget on real content.

## 2. LLM discovery files

- `public/llms.txt` — one-screen index: author E-E-A-T block, core pages, all
  10 topic hubs, all 23 articles grouped by family, citation policy.
- `public/llms-full.txt` — the same content expanded to per-page summaries with
  `lastmod` dates for single-fetch ingestion.
- Generated by `tools/build-llms-txt.mjs` (`npm run llms`, drift check
  `npm run llms:check`). Regenerate whenever a page is added, renamed or moved.

## 3. Structured data for answers (E-E-A-T signals)

Every page ships a machine-readable identity that answer engines reuse:

- Author identity is consistent everywhere: `Person` "Akash Nagapure" with
  `jobTitle`, `worksFor: Hexaware`, `sameAs` (LinkedIn + GitHub), `knowsAbout[13]`.
- The blog hub (`Projects.html` → `CollectionPage`) carries an `ItemList` of all
  23 `BlogPosting` nodes, so engines can traverse the whole library from one fetch.
- Every article has dates + publisher + `mainEntityOfPage` + `wordCount`, so
  freshness and provenance are unambiguous.
- FAQPage schema mirrors the visible FAQ text 1:1 (never ship answers in JSON
  that are not on the page — Google drops mismatched FAQ rich results).

Run `npm run seo:validate` before release; zero problems is the gate.

## 4. Content patterns that win citations

- Question-led headings: each article's H1/H2s read as questions AI users ask
  ("How do I fix Autopilot ESP timeouts?") — match the heading to the query.
- Direct answers first: the first 1–2 sentences of each section state the
  conclusion, then the steps. Snippets and AI answers quote the first block.
- Self-contained sections: every H2 section restates enough context to be cited
  standalone (engines quote sections, not whole pages).
- Statistics + specifics over adjectives: "35,000+ endpoints", "10+ years",
  "23 guides" — numbers get cited, superlatives don't.
- Author byline on every article (same name, same spelling, same links) so all
  engines converge on one entity.

## 5. Freshness & monitoring

- `sitemap.xml` `<lastmod>` is regenerated per file mtime (`npm run sitemap`).
- Search Console: track `Impressions` for question queries + the FAQ/Article
  enhancement reports; fix any schema warnings within a release.
- Spot-check monthly in ChatGPT, Perplexity and Google (AI Mode) with prompts
  like "who manages 35,000 Intune endpoints guides" and
  "Intune Win32 packaging step by step" — the site pages should appear or be cited.
- When a new article ships: `npm run seo:blogs && npm run sitemap && npm run llms`
  so the new URL is reachable from sitemap, llms.txt AND the hub ItemList.
